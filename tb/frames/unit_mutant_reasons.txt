# tb/frames/unit_mutant_reasons.txt: why make frames-unit-mutants' survivors are caught only by their own unit gate (PLAN
# M13 "Mutants"; tools/gate/frames_unit_mutants.py --report prints them). A line: <id> | <reason>. Two kinds:
#   [invisible]    the mutant changes state, order or timing that the unit testbench compares but that never reaches
#                  video memory in the whole core (the frame gate compares only video memory after each render)
#   [not reached]  the mutant does change values, but only on inputs that make frames' subset (99 pages at most 8
#                  renders, 33 dumps, seeds 1-200) does not contain; the unit gate's probe has them (named)
# Written from the 2026-11-25 run (agents/m13/gates/frames-unit-mutants.summary.txt): 24 survivors of 165.
isp_tile.tag-29-bits | [invisible] tagA's bits 31:29 (a background tag's) are compared by the isp-tile testbench at every phase; the TSP reads the tag's parameter offset (bits 23:3) and the bits 31:29 only decide a KeyAbove tie against TAG_BELOW, which no subset render has
isp_tile.m7.quad-lag-off | [invisible] the punch-through chunk boundary moves by one quad's vertex count: the isp-tile testbench compares each chunk's passes and state at the phase halts; in the subset's renders (ptchunklag's first 8, ptlayers, ...) the moved boundary resolves the same final pixels (ptchunkq, the probe's other case, is not in the subset)
isp_tile.m7.threshold-unsigned | [not reached] chunk sizes 0 and 1 (the threshold S - 2 negative) come from scenegen's PT sizes 0 / 1; the subset's renders with punch-through and those sizes resolve the same pixels in one chunk as in many (the testbench compares the chunks themselves)
isp_tile.m7.presort-volume-break | [not reached] pre-sorted runs cut at volume edges restart the TSP's planes there; only a pre-sorted translucent polygon over a modifier volume edge shows it (uvrun kind 6: uvrun's renders past the subset's 8; scenegen TRANS with MODVOL), and the run boundaries are compared directly by the isp-tile testbench
isp_tile.m7.pcache-reverse | [invisible] the replay's order only matters for equal depth keys (ties by list order) and tag ties; the subset's later passes have no such tie, the testbench compares the fragment order itself
isp_tile.m7.cut-eop-from-flops | [invisible] the end-of-pass flag of TR_PRESORT's last run, read after the next primitive rewrote the rows: the testbench checks every run item's flags; in the whole core the TSP's pass end follows the entry's end, so the pictures agree
isp_tile.m7.fb-anyfail-pass-done-only | [invisible] by construction: in p2_core the TSP's PASS_DONE carries the pass's anyfail, so taking it alone gives the same answer; only the isp-tile testbench drives PASS_DONE with 0 and the PIXEL fails separately
sort.window-97 | [invisible] a 97-place window changes the span sorter's output order (timemeas order), not a value: the TSP's results do not depend on the run order beyond what the ISP's passes fix; the sort gate compares the order with refsw3's SpanSort
sort.new-drain-every-item | [invisible] the TSP look-ahead's drain start on every item changes when p2_tsp_store refills (clocks), not what it shades; the sort gate's random streams check the signal
tsp_setup.k2-plus-one | [not reached] MipSelect's length constant off by one moves K only at 2^-28: the console sets (mipk4) have the primitives where the level flips; the subset's mipmapped pages and dumps none
tsp_setup.dropped-as-plus-zero | [not reached] a dropped offset plane's -0 against +0 shows only as one unit on a negative-zero offset colour (seen(-0) = -2^-127); the unit gate's a3 class makes it, the subset has none
tsp_setup.flat-c-and-rule | [not reached] the flat branch's C sign rule (the table before 2bee80f2) differs only on 1/w terms of mixed signs in a flat primitive (a3 class); no subset primitive
tsp_setup.drop-on-sent | [invisible] the drop predicate on the sent offset colours instead of the scaled ones changes the drop class, not a value (its own description: "the class: no value changes"); the unit gate compares the class
tsp_setup.fp.zero-reach-3 | [not reached] the TSP adders' zero rule at 2^-124 against 2^-125 .. 1.5 x 2^-125 of the other sign: only console set cwsum1's sums; no subset sum is that small
tsp_run.ww-clamp-off | [not reached] w x w above 2^127 (mipmeas mwext1's extreme w): no subset primitive has such a w
tsp_run.pt-volume | [not reached] InVolume in the punch-through passes matters only for a punch-through polygon inside a two-volume modifier (the random class has them); the subset's modifier-volume pages have none under punch-through
tsp_run.ss-order | [invisible] SupSample's four points are averaged; swapping (1, 0) and (0, 1) changes each point (the tsp-run testbench's super class compares them) but not their sum, so not the pixel
tsp_run.dz-off | [not reached] a zero determinant's level (dzForce) against d's: the subset's Sdet = 0 primitives (tsp2_mipdz's first renders) have d already past the last level; the random class has the others
tsp_run.fp.zero-den-127 | [not reached] a zero denominator read as 2^-127: only uvmeas wzero2's readings divide by zero there; no subset pixel
tsp_tile.anyfail-ro | [not reached] PASS_DONE's anyfail counting run-only pixels changes a punch-through pass's continuation only where a run-only pixel fails the alpha test; the unit gate's shade class makes it, the subset (ptruns' first 8 renders) does not
tsp_tile.alpha-ref-8 | [not reached] PT_ALPHA_REF's bits above the low byte are 0 in every subset render (the tests and games write 8-bit values); the shade class writes random words
wout.row-11-bits | [not reached] the scaler's stream row counter differs at 11 bits only from row 1024 of a stream; the subset's frames have at most 1,024 lines (scenegen's FB_Y_CLIP 1023), the wout testbench's random frames go further
wout.strip-parity | [not reached] the parity picks FB_W_SOF2 for odd strips; the five subset renders with the strip buffer on (scenegen seeds 29, 69, 121, 135, 175) have 0 strip lines (FB_R_CTRL[21:16] = 0: no strip written), so no odd strip is ever written; the wout testbench's random frames have strips (1,688 of 10,000)
wout.field-start | [not reached] the field start (pos 1024) without the filter needs interlace and field select at a vertical scale of 0x400 or less; the subset's ten such renders are at 0x800 (the filter on: the same start both ways) or 0x400 (sof2probe's two, whose frames come out equal: a direct copy), the wout testbench's random factors show it
